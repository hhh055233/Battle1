# 🐔 Chicken Royale

משחק באטל רויאל תלת-ממדי שרץ ישר בדפדפן, בהשראת **PUBG: Battlegrounds** ו-**Shell Shockers**.
חינם ובלי התקנה: מנהל החדר פותח חדר, שולח לחברים קוד בן 5 תווים (או קישור), ועד **50 שחקנים** נכנסים לאותו משחק.
מקומות שנשארו ריקים אפשר להשלים בבוטים.

יש שני אופנים לשחק, ושניהם באותו אתר:

| אופן | מי מריץ את המשחק | מתי מתאים |
|---|---|---|
| **P2P** (ברירת מחדל, בלי שרת) | הדפדפן של מנהל החדר | אפס הגדרות; המחשב והחיבור של המנהל נושאים את כל העומס |
| **שרת ייעודי** (`server/`) | תהליך Node אחד שרץ ברציפות | **50 שחקנים**, ואף אחד לא תלוי במחשב של המנהל |

> האתר הוא קבצים סטטיים בלבד (HTML + JavaScript בלי שלב build), ולכן הוא מתאים ל-Vercel בלי שום הגדרה מיוחדת.

## הפעלה מקומית (לבדיקה)

```bash
npm install          # פעם אחת (מתקין את ws)
npm start            # שרת המשחק + האתר על http://localhost:8080  (דורש Node 18+)
# או רק האתר, בלי שרת משחק (מצב P2P בלבד):
npm run dev          # או: python3 -m http.server 8080
```

פותחים `http://localhost:8080`. חובה לגשת דרך שרת (לא לפתוח את `index.html` ישירות מהדיסק), כי המשחק משתמש במודולי ES.

## פריסה ל-Vercel

**אפשרות א׳ – שורת פקודה (הכי מהיר)**

```bash
npm i -g vercel
cd battle-royale
vercel            # בפעם הראשונה: התחברות ואישור ברירות המחדל → מקבלים כתובת preview
vercel --prod     # כתובת קבועה (למשל chicken-royale.vercel.app)
```

**אפשרות ב׳ – GitHub**

1. מעלים את התיקייה לריפו ב-GitHub.
2. ב-[vercel.com/new](https://vercel.com/new) בוחרים *Import* לריפו.
3. **Framework Preset: Other**, משאירים *Build Command* ו-*Output Directory* ריקים, ולוחצים Deploy.

אין משתני סביבה, אין פונקציות שרת ואין מסד נתונים. התוכנית החינמית של Vercel מספיקה (לאתר עצמו; שרת המשחק הייעודי רץ במקום אחר – ראו הסעיף "שרת משחק ייעודי").

### (אופציונלי) להיפטר מהתלות ב-CDN

כברירת מחדל האתר טוען את `three.js` ו-`PeerJS` מ-jsDelivr (עם גיבוי ל-unpkg). אם רוצים שהכול יישב אצלכם:

```bash
npm run vendor    # מוריד את שני הקבצים לתיקיית vendor/
```

והעלו את התיקייה `vendor/` יחד עם שאר הקבצים. האתר מעדיף אוטומטית את `vendor/` אם הוא קיים.

## שרת משחק ייעודי (לשחק עם 50 מחשבים)

במצב P2P הדפדפן של מנהל החדר מריץ את כל הסימולציה ומשדר לכל השחקנים – זה כבד, ואם המנהל נופל המשחק נגמר לכולם.
הפתרון הוא `server/server.mjs`: שרת Node קטן (תלות אחת: `ws`) שמריץ **את אותה סימולציה בדיוק** בלי דפדפן. כל השחקנים, כולל המנהל, הם לקוחות רגילים, והחדרים, הקודים וההגדרות עובדים אותו דבר.

**למה לא על Vercel?** פונקציות של Vercel קצרות-חיים (עד 5 דקות בתוכנית החינמית) ואין להן זיכרון משותף בין בקשות, ולכן הן לא יכולות להחזיק משחק חי. את האתר שמים ב-Vercel, ואת שרת המשחק מריצים אצל ספק שמריץ תהליך רציף (Render, Railway, Fly.io, VPS וכו׳).

### הרצה מקומית

```bash
npm install
npm start            # http://localhost:8080 – השרת מגיש גם את האתר עצמו
npm run loadtest     # בדיקה אוטומטית: 50 שחקנים מדומים, כולל כמה משחקים רצופים
```

### פריסה ב-Render (חינם לבדיקות)

1. מעלים את הפרויקט ל-GitHub.
2. ב-[render.com](https://render.com): **New → Blueprint** → בוחרים את הריפו → **Deploy**. הקובץ `render.yaml` כבר מגדיר הכול.
3. מקבלים כתובת כמו `https://chicken-royale.onrender.com`. היא כבר משחקת, כי השרת מגיש גם את האתר.

ב-`render.yaml` מוגדר אזור Frankfurt, הקרוב ביותר לישראל, כדי שההשהיה במשחק תהיה נמוכה.

התוכנית החינמית של Render "נרדמת" אחרי כ-15 דקות בלי תנועה (הכניסה הראשונה אחר כך לוקחת כחצי דקה) ומקבלת מעט מאוד CPU, ולכן היא מתאימה לבדיקות. למשחקי 50 שחקנים כדאי תוכנית בתשלום קטנה (Starter) או VPS.
אותו `Dockerfile` עובד גם ב-Railway, Fly.io וכל שרת עם Docker.

### לחבר את האתר שב-Vercel לשרת

אחת משתי דרכים:

- **קבועה:** בקובץ `config.js` כותבים `export const SERVER_URL = 'wss://YOUR-SERVER.onrender.com/ws';` ופורסים מחדש.
- **בקישור:** `https://האתר-שלכם/?server=wss://YOUR-SERVER.onrender.com/ws`. הכתובת נשמרת בדפדפן, וקישור ההזמנה שמנהל החדר מעתיק כבר כולל אותה. `?server=off` מכבה את המצב.

כשהאתר ב-`https`, כתובת השרת חייבת להיות `wss://` (דפדפנים חוסמים `ws://`). אם השרת לא זמין, המשחק חוזר אוטומטית למצב P2P.

### משתני סביבה (כולם אופציונליים)

| משתנה | ברירת מחדל | משמעות |
|---|---|---|
| `PORT` | `8080` | הפורט (ספקי אחסון מגדירים לבד) |
| `MAX_ROOMS` | `8` | כמה חדרים במקביל |
| `ALLOWED_ORIGINS` | הכול מותר | רשימת origins מופרדת בפסיקים שמותר להם להתחבר, למשל `https://chicken-royale.vercel.app` |
| `SERVE_STATIC` | `1` | `0` = השרת מגיש רק WebSocket (כשהאתר יושב ב-Vercel) |
| `EMPTY_GRACE_MS` | `30000` | כמה זמן חדר ריק נשמר לפני שהוא נסגר |
| `AUTO_RESET_MS` | `120000` | אחרי סיום משחק: חזרה אוטומטית ללובי אם המנהל לא לחץ |

`GET /health` מחזיר מספר חדרים ושחקנים, זיכרון וזמן CPU. אם המנהל יוצא באמצע משחק, השליטה בחדר עוברת לשחקן אחר והמשחק ממשיך.

**מדידות (50 שחקנים מדומים על מחשב אחד, בשלב המטוס):** כ-6 KB/s לשחקן (כ-315 KB/s בסך הכול), כ-2% מליבה אחת וכ-90 MB זיכרון. משחק אמיתי עם קרבות ובוטים יעמיס יותר, וזה לא נמדד.

## איך משחקים עם חברים

1. נכנסים לאתר, כותבים שם, ולוחצים **צור חדר**. מקבלים קוד בן 5 תווים ובלובי כפתור **העתק קישור**.
2. החברים נכנסים לאותו אתר, כותבים את הקוד ולוחצים **הצטרף** (או פותחים את הקישור `…/?room=CODE`).
3. מנהל החדר קובע בלובי:
   - מקסימום שחקנים (2–50) ומספר בוטים שמשלימים את החדר (0–49)
   - מהירות האזור הכחול: רגילה / מהירה / מהירה מאוד / בליץ׳
   - רמת הבוטים: קלה / בינונית / קשה
   - מצלמה: גוף ראשון + שלישי / גוף ראשון בלבד / גוף שלישי בלבד
   - שעה ביום: יום / שקיעה / לילה, וערפל רגיל או כבד
4. לוחצים **התחל משחק**. כולם עולים על המטוס.
5. בסוף המשחק חוזרים ללובי ואפשר להתחיל סיבוב נוסף באותו חדר.

**חשוב לדעת (מצב P2P, בלי שרת):** הסימולציה של המשחק רצה בדפדפן של מנהל החדר, והשחקנים האחרים מתחברים אליו ישירות (WebRTC דרך PeerJS, שירות האיתות החינמי שלהם). לכן:
- מנהל החדר צריך את המחשב החזק והחיבור היציב ביותר, ואסור לו לסגור את הלשונית (אם הוא סוגר – המשחק נגמר לכולם).
- אין צורך לפתוח פורטים. אם שחקן לא מצליח להתחבר, בדרך כלל עוזר לנסות רשת אחרת (למשל נתוני סלולר).

עם **שרת ייעודי** (ראו הסעיף "שרת משחק ייעודי") שום דבר מזה לא נכון: המשחק רץ על השרת, כולם רק לקוחות, ואם המנהל יוצא השליטה עוברת לשחקן אחר.

## מה יש במשחק

**מפה** – אי בגודל 1.6×1.6 ק״מ שנוצר מ-seed אחד (כל השחקנים מקבלים בדיוק אותה מפה): 11 אתרים (עיירה ישנה, נמל, בסיס צבאי, שדה תעופה, בית חולים, בית ספר, חווה, מחצבה, כפר מגדלור, כפר נהר ומזחי צפון), כבישים שמחברים ביניהם, בניינים עם כמה קומות, מדרגות וריהוט, גגות משופעים, מכוניות, מכולות, יער אורנים ואלונים, סלעים ושיחים.

**נשקים (17)** – אקדחים: P92, P18C, Desert Eagle · תת-מקלעים: Micro UZI, UMP45, Vector · רובי סער: M416, SCAR-L, AKM, Groza · מקלע: M249 · צלפי חצי-אוטומטי: SKS, Mini 14 · צלפים: Kar98k, AWM · שוטגנים: S12K, S686.
כוונות: נקודה אדומה, x2, x4, x8. תחמושת לפי סוג: 9mm, .45, 5.56, 7.62, 12 gauge, .300 Magnum. לכל נשק רתע, פיזור, טווח וירידת נזק.

**ציוד מגן** – קסדות, אפודים ותיקי גב ברמות 1–3 (הפחתת נזק 30% / 40% / 55% עם עמידות שנשחקת, תיק גב מגדיל את קיבולת התיק). קסדת ספצנאז (רמה 3) מופיעה רק בחבילות אספקה, ואפוד ותיק ברמה 3 נדירים גם ברצפה.

**רימונים** – רסס (אפשר לבשל לפני הזריקה), עשן, הלם (הבזק מסנוור וצלצול באוזניים) ובקבוק מולוטוב שיוצר שטח אש.

**תרופות** – תחבושת, ערכת עזרה ראשונה, ערכת רפואה, משקה אנרגיה, משכך כאבים ואדרנלין (בוסטים).

**מהלך משחק** – מטוס שחוצה את האי → קפיצה ובחירת נחיתה → איסוף ציוד → אזור כחול שמתכווץ ב-8 שלבים (מ-760 מ׳ עד 0, והנזק מטפס מ-0.4 ל-12 לשנייה) → ניצחון אחרון שנשאר.

**חבילות אספקה** – מטוס מפיל חבילה עם מצנח ועשן פעם בכ-105 שניות (6 במשחק, בקצב רגיל), בתוך האזור הבטוח. בתוכה ציוד נדיר: AWM, M249, Groza, Kar98k, M416 ורמה 3 של קסדה, אפוד ותיק.

**בוטים** – קופצים מהמטוס, נוחתים, מחפשים לוט, נלחמים, זורקים רימונים, מתרפאים ובורחים מהאזור הכחול. אחרי מוות כל שחקן (ובוט) משאיר את הציוד שלו על הרצפה.

**ממשק** – מצפן, מיני-מפה ומפה גדולה, killfeed, צ׳אט, מצב צפייה אחרי מוות, תיק עם קיבולת, מד חיים ובוסט, אינדיקציית נזק, צלילים פרוצדורליים. כל הגרפיקה והאודיו נוצרים בקוד – אין קבצי תמונה או שמע חיצוניים.

## מגבלות ידועות

- **נבדק בסימולציה אוטומטית (Node) ולא בדפדפן אמיתי עם כרטיס מסך.** הלוגיקה, הרשת והחדרים נבדקו מקצה לקצה, אבל המראה והביצועים בפועל לא נבדקו – ייתכנו באגים ויזואליים או צורך בכוונון. אם משהו נראה או מרגיש לא טוב – כל המספרים מרוכזים בקבצים קטנים וקל לכוונן אותם (ראו "התאמות מהירות").
- אין רכבים נהיגים (המכוניות הן קישוט).
- מקלדת ועכבר בלבד, אין תמיכה במגע או בג׳ויסטיק.
- זיהוי פגיעות נעשה בצד השחקן ומאומת בצד המארח בבדיקות שפיות. מתאים למשחק עם חברים, לא למשחק תחרותי נגד זרים (אפשר לרמות).
- במצב P2P: אם מנהל החדר סוגר את הלשונית או מאבד חיבור, המשחק נגמר לכולם (בשרת ייעודי – לא).
- השרת הייעודי נבדק מול 50 לקוחות מדומים (בלי גרפיקה) ומול ממשק האתר בסימולציה, לא מול 50 דפדפנים אמיתיים.
- דפדפן מודרני נדרש (Chrome, Edge, Firefox או Safari 16.4 ומעלה) עם WebGL.
- אם המשחק איטי: ב-Esc אפשר להנמיך את איכות הצללים או לכבות אותם, ולכווץ את חלון הדפדפן.

## התאמות מהירות

- **קצב ונזק של נשק, ציוד, שלבי האזור, מהירות המטוס** – `js/sim/data.js`.
- **מיקומי האתרים, צפיפות היער והלוט** – `js/sim/worldgen.js` ו-`js/sim/loot.js`.
- **צבעי שמיים ושעות היום** – `TIME_PRESETS` ב-`js/render/worldmesh.js`.
- שים לב: המפה והלוט נוצרים מ-seed דטרמיניסטי, ולכן שינוי בקוד היצירה חייב להגיע לכל השחקנים (פשוט פורסים מחדש – כולם טוענים את אותה גרסה).
